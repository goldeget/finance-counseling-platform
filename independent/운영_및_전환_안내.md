# 금융상담 플랫폼 독립 운영 안내

작성 기준: 2026-11-12 한국시간. 이 문서는 시험과 전환 준비 상태를 기록하며, 출시 완료 확인서가 아닙니다.

## 현재 구성

1. 고객이 접속하는 `loan.climekr.com`은 현재 기존 Sites 서비스입니다. 독립 Cloudflare Worker로 아직 전환하지 않았습니다.
2. 소스는 비공개 GitHub 저장소 `goldeget/finance-counseling-platform`의 `main` 브랜치에 있습니다. `independent-staging` 브랜치에는 시험 구현 이력이 있습니다. Cloudflare Workers Builds가 시험용 Worker, 조회 전용 운영 후보, 기존 사이트의 임시 파기 Worker에 연결되어 있습니다. 이 빌드들은 계정에 기존에 있던 `workflows-starter-template build token`을 공유하므로 그 토큰을 삭제하면 빌드가 중단됩니다. Supabase 후기 관리자 함수와 기존 Sites 본체의 배포는 이 GitHub 자동 배포에 포함되지 않습니다.
3. 독립 시험용 Worker와 운영용 후보 Worker가 따로 있습니다. 운영용 후보에는 관리자 주소 `admin-loan.climekr.com`이 연결되어 있고, 전환 전에는 조회 전용입니다. 고객 주소는 아직 기존 사이트를 사용합니다. 원본 사이트를 대체하기 전에 최종 동기화와 실제 도메인 시험이 필요합니다.
4. 상담 접수는 암호화하여 전용 Cloudflare D1에, 후기는 별도 Supabase 프로젝트 `finance-counseling-reviews`에 저장하는 구성입니다. 다른 유심 사이트의 저장소와 구분했습니다.
5. 관리자 접근은 Cloudflare Access의 이메일 일회용 인증과 서버의 서명 검증을 함께 사용합니다. 시험 관리자 화면에서 로그인, 후기 등록 및 삭제를 확인했습니다. 운영 관리자 주소의 비로그인 접근이 인증 화면으로 이동하는 것도 확인했습니다. 전환 중에는 운영 후보의 접수·관리 변경과 후기 함수의 직접 변경을 막습니다. 운영 관리자 도메인에서의 최종 로그인과 실제 권한은 전환 전에 다시 확인해야 합니다.

## 자료 이전과 개인정보 보관

- 2026-11-12 03시경 기존 사이트에서 후기 108,250건과 상담 접수 11건을 다시 복사·대조했으며 직전 이전 자료와 변경된 항목이 없었습니다. 접수는 암호화하여 복사했고 후기 번호, 작성자, 출처, 본문, 별점 및 날짜를 대조했습니다. 원본이 계속 운영되고 있으므로 이 숫자는 전환 직전 숫자를 뜻하지 않습니다.
- 독립 Worker에는 접수 시점부터 1년이 지난 상담 접수를 정기 삭제하는 기능이 있습니다. 매일 한국시간 03:00 실행 일정이 설정되어 있으며, 시험 환경에서 오래된 시험 접수만 삭제되는 것을 확인했습니다. 운영 후보에서도 2026-11-12 03:00 실행 기록을 확인했고, 기한이 지난 접수가 없어 삭제 건수는 0건이었습니다.
- 현재 운영 중인 기존 사이트에도 별도의 임시 파기 연결을 적용했습니다. 인증되지 않은 호출은 차단되며, Cloudflare의 실제 시험 정기 실행이 성공했습니다. 현재 실행 일정은 매일 한국시간 03:30입니다. 사이트에는 1년 보관과 별도 백업 안내가 표시됩니다. 독립 서비스 전환을 마친 뒤에는 기존 사이트용 `finance-legacy-retention` 일정과 보호 경로를 정리해야 합니다. 정기 실행 실패에 대한 별도 알림은 아직 설정되지 않았습니다.
- GitHub Actions의 `Current site availability and retention fallback`은 매일 한국시간 04:00에 기존 사이트의 접속·1년 보관 안내·후기 응답과 독립 관리자 인증 이동을 점검하고, 같은 보호 경로를 호출해 만료 접수 삭제를 한 번 더 시도합니다. 실행 실패는 Actions 기록에서 확인할 수 있으며, 이메일 알림의 실제 수신 여부는 별도 설정 확인이 필요합니다. 이 점검이 성공해도 Cloudflare 정기 실행 자체의 성공을 증명하지는 않습니다. 독립 서비스 전환 후에는 기존 사이트용 점검을 새 운영 구성에 맞게 변경해야 합니다.
- D1의 시점 복구 자료와 이전 작업용 F 드라이브 암호화 복사본에는 별도의 보존 기간과 삭제 절차가 필요합니다. 이전 작업용 복사본을 영구 보관하면 본 저장소의 삭제만으로 모든 복사본이 삭제되는 것은 아닙니다. 전환 검증 후 해당 임시 복사본을 정리하고, 이후 만들어지는 백업에도 보관기간과 파기 절차를 적용해야 합니다.
- Cloudflare 무료 요금제의 D1 시점 복구는 최대 7일 범위입니다. 별도의 시험 데이터베이스에 임의 자료를 넣고 실제로 이전 시점 복원에 성공했습니다. 이는 고객 데이터베이스 자체의 실복원이나 계정 장애에 대비한 별도 사본 복구를 검증했다는 뜻은 아닙니다. https://developers.cloudflare.com/d1/reference/time-travel/
- 후기 백업 작업은 매주 화·목·토요일 한국시간 오전 3시 10분에 실행하도록 구성했습니다. 원본을 두 번 대조한 뒤 압축 파일을 만들고, 임시 데이터베이스 복원과 무결성 검사를 통과해야 GitHub 비공개 저장소의 실행 결과에 14일 동안 보관합니다. 첫 클라우드 실행에 성공했으며, 파일을 다시 내려받아 후기 108,250건을 임시 데이터베이스에 복원했습니다. 고객 상담 접수는 이 후기 백업에 포함되지 않습니다. 전환 전까지는 신규 저장소의 백업이므로 기존 사이트의 이후 변경분이 빠질 수 있습니다. 후기 삭제 후 기존 백업에서 해당 내용이 즉시 사라지는 방식은 아니므로 삭제 요청 처리 시 백업도 관리해야 합니다.
- 암호화 키는 Cloudflare의 Worker 비밀 설정과 비공개 GitHub 저장소의 Actions 비밀 설정에 보관하며, 이 PC의 현재 Windows 계정에서만 복원 가능한 보호 사본도 F 드라이브에 있습니다. GitHub 비밀을 사용해 가상의 암호화 자료를 복구하는 시험은 성공했습니다. GitHub 비밀은 화면에서 다시 읽을 수 없고 실제 새 계정에 배포하는 복구 절차는 아직 시험하지 않았습니다. PC 사본도 다른 PC나 Windows 계정으로 옮겨 복구할 수 있다는 뜻이 아닙니다. 키나 고객 자료를 GitHub 소스에 올리거나 채팅으로 공유하지 마세요.
- 2026-11-12 추가 검사에서 운영 후보의 암호화 접수 11건이 이전에 만든 F 드라이브 암호화 사본과 일치했습니다. 이 PC 계정의 보호된 키를 사용해 그 사본을 메모리 전용 시험 데이터베이스에 넣고 11건 모두 복호화되는 것을 확인했습니다. 기존 사이트의 접수 번호·시각도 운영 후보와 일치했지만, 이 검사는 전환을 위한 쓰기 중단 상태에서 수행하지 않았고 기존 사이트의 현재 본문 전체나 별도 계정 복구를 확인한 것은 아닙니다. F 드라이브 복사본은 자동 생성·만료되는 운영 백업이 아닙니다.
- F 드라이브는 USB FAT32 볼륨이며 Windows가 파일 시스템의 검사 필요 상태를 보고했습니다. 물리 디스크 상태는 정상으로 표시되지만 F 드라이브 사본 하나만 유일한 복구 수단으로 삼지 마세요. 이 작업에서는 디스크 복구 명령을 실행하지 않았습니다.

## 운영 전환 전 남은 작업

1. 기존 사이트의 신규 접수와 후기 변경을 짧은 전환 구간에 통제하고, 그 시점의 모든 변경·삭제를 새 저장소에 반영해 건수와 내용을 대조합니다. 단순한 최초 복사만으로 전환하면 그 이후의 고객 접수가 누락될 수 있습니다.
2. 운영 관리자 도메인과 후기 관리자 함수가 모두 운영용 Cloudflare Access 설정을 검증하는지 확인하고, 전환 준비가 끝난 뒤 Worker와 후기 함수의 `MIGRATION_READ_ONLY`를 함께 해제합니다. 시험용 관리자에서 운영 후기를 수정할 수 없게 유지합니다.
3. 운영 Worker와 `loan.climekr.com` 연결 및 TLS, 관리자 로그인, PC·모바일 상담 접수와 접수 결과, 후기 목록, 파기 일정과 장애 시 복구를 검증합니다. 기존 서비스와 DNS의 복구 방법을 준비한 뒤 연결을 전환합니다. 전환 후 기존 사이트용 임시 파기 일정과 보호 경로, 보관기간이 정해지지 않은 이전 임시 사본도 정리합니다.
4. Worker 자동 배포는 연결되었습니다. 현재 기존 공유 빌드 토큰을 사용하므로 독립적인 전용 토큰을 마련하고, Supabase 후기 관리자 함수 배포·복구 절차를 완성합니다. 참고: https://developers.cloudflare.com/workers/ci-cd/builds/api-reference/
5. 정기 백업과 복원, 키 복구, 오류 감시 및 파기 실패 알림을 완성합니다. Supabase 무료 프로젝트는 활동이 적으면 일시 중지될 수 있고 무료 요금제에서 내려받을 수 있는 자동 백업을 제공하지 않습니다. 운영 요구에 맞춰 별도 백업 또는 유료 요금제를 결정해야 합니다. 참고: https://supabase.com/docs/guides/platform/free-project-pausing 및 https://supabase.com/docs/guides/deployment/going-into-prod
6. 카카오톡과 채널톡은 사용자가 주소를 제공한 뒤 연결합니다. 현재 독립 관리자 화면에는 후기 CSV 일괄 등록 기능이 없습니다.

## 일상 관리

- 코드 수정은 비공개 저장소에서 검토하고 시험 환경에서 검사합니다. GitHub 자동 검사는 화면 파일 생성과 서버 기능 검사를 수행하며 실제 서비스 배포는 하지 않습니다. 직접 검사할 때는 `node independent/build.mjs`와 `node --test independent/tests/*.test.mjs`를 사용합니다.
- Cloudflare와 Supabase의 소유자 계정 및 인증 수단을 안전하게 관리합니다. ChatGPT 구독이 종료되어도 이 계정과 저장소를 통해 운영할 수 있도록 배포와 복구 절차를 완성해야 합니다.
- 연락 채널을 연결하기 전에는 상담 접수 후 운영자가 관리자 화면에서 접수 내역을 확인해야 합니다. 실제 대출 승인·금리는 상담 및 심사 결과에 따라 확인하며, 화면의 희망 조건과 월 상환액은 입력값에 따른 예시입니다.
